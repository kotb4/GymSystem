# جيم برو (GymSystem) — نظام إدارة الصالات الرياضية

نظام إدارة جيم عربي بالكامل (**RTL First**) بواجهة **Dark Premium** بلمسات Neon، يعمل **بدون إنترنت** بالكامل.

المعمارية الحالية: **تطبيق سطح مكتب عمليًا** — الواجهة (WebView) للعرض فقط، وكل بيانات النظام محفوظة في **ملف SQLite حقيقي على القرص** يملكه باك-اند محلي يعمل على نفس الجهاز.

> **لا تُحفظ أي بيانات أعمال في المتصفح**: لا IndexedDB، ولا localStorage، ولا sessionStorage. مسح كاش المتصفح لا يؤثر على البيانات إطلاقًا، وتحديثات النظام تُحمَّل تلقائيًا دون أي تدخل يدوي.

---

## المعمارية

```
الواجهة (React SPA داخل نافذة تطبيق)
        │  HTTP على 127.0.0.1 فقط
        ▼
الباك-اند المحلي (Node.js)  ← منطق الأعمال، الصلاحيات، المعاملات، النسخ الاحتياطي
        │
        ▼
SQLite حقيقي (gym.db)  +  ملفات النظام على القرص
```

- **مصدر واحد للحقيقة**: `Database/gym.db` — يبقى موجودًا بعد إغلاق التطبيق، إعادة تشغيل الجهاز، مسح الكاش، أو تحديث النظام.
- **الأمان**: الباك-اند يستمع على `127.0.0.1` فقط (ليس مكشوفًا على الشبكة)، والجلسات تُدار بخُطافات HttpOnly مخزنة في قاعدة البيانات نفسها.
- **منطق أعمال واحد**: طبقة الخدمات في `src/core/services/` تعمل الآن **داخل الباك-اند فقط**؛ الواجهة تناديها عبر RPC مُقيَّد بقائمة بيضاء.

## التقنيات

| الأداة | الاستخدام |
| --- | --- |
| Node.js 24+ (`node:sqlite`) | باك-اند محلي + SQLite متزامن بدون أي native build |
| Vite + React 19 + TypeScript strict | الواجهة (بناء سريع، `base: "./"`) |
| Tailwind CSS v4 | Design Tokens عبر `@theme` + Logical Properties للـ RTL |
| esbuild | تجميع الباك-اند في ملف واحد `dist-server/index.cjs` |
| Cairo Variable | خط عربي محمّل محليًا (أوفلاين) |
| lucide-react | أيقونات بدون Emoji |

## التشغيل

### الإنتاج (للاستخدام الفعلي)

```bat
npm run build          :: يبني الواجهة (dist/) والباك-اند (dist-server/)
scripts\windows\start-gymsystem.bat
```

السكربت يشغّل الباك-اند مصغَّرًا، ينتظر جهوزية الـ API، ثم يفتح نافذة التطبيق (Edge App Mode). أول تشغيل يعرض شاشة تهيئة لإنشاء حساب المالك.

### التطوير

```bash
npm install
npm run dev:server     # طرفية 1: بناء + تشغيل الباك-اند على 127.0.0.1:8890
npm run dev            # طرفية 2: واجهة Vite على 5173 مع proxy للـ /api
```

أو مباشرة: `dev.bat` (يشغّل الاثنين معًا).

### سكربتات npm

| السكربت | الوظيفة |
| --- | --- |
| `npm run dev` | واجهة Vite للتطوير (proxy للـ API) |
| `npm run dev:server` | بناء + تشغيل الباك-اند |
| `npm run build` | فحص TypeScript (واجهة + باك-اند) ثم بناء الاثنين |
| `npm start` | تشغيل الباك-اند المبني (يقدّم dist/) |
| `npm run typecheck` / `typecheck:server` | فحص أنواع منفصل |
| `npm test` | اختبارات الوحدة (Vitest) |
| `npm run e2e` | اختبار E2E شامل للباك-اند (تشغيل → بيانات → إيقاف → إعادة تشغيل → تحقق) |

**بيانات تجريبية (اختياري، للتطوير فقط):**
```bash
set GYM_SEED_DEMO=1 && npm run dev:server
```

## أماكن تخزين البيانات

كل شيء تحت `%LOCALAPPDATA%\GymSystem\` (قابل للتغيير بمتغير البيئة `GYMSYSTEM_DATA_DIR`):

```
%LOCALAPPDATA%\GymSystem\
├── Database\
│   └── gym.db            ← قاعدة البيانات الأساسية (SQLite + WAL)
├── Files\                ← للأصول المستقبلية (صور الأعضاء، مرفقات…)
├── Backups\              ← نسخ .gymbak (يدوية/تلقائية/وقائية قبل الاستعادة)
├── Logs\
│   └── server.log        ← سجل الباك-اند
└── Config\
```

- **النسخ الاحتياطي**: زر «إنشاء نسخة وتنزيلها» في صفحة الصيانة ينشئ snapshot موثّع (فحص integrity قبل التسجيل) ويحمّله لك ملفًا؛ النسخ التلقائية تعتمد إعدادات الفترة والاحتفاظ.
- **الاستعادة**: ترفع ملف `.gymbak` → يتم فحصه (SQLite header + integrity_check + وجود مستخدمين) → تُؤخذ نسخة وقائية من الوضع الحالي → استبدال ذرّي للملف → تقرير أعداد الجداول. بعد الاستعادة يجب تسجيل الدخول من جديد (الجلسات جزء من القاعدة).
- **ترحيل النسخة القديمة (من المتصفح)**: عند أول تشغيل، إذا وُجدت قاعدة قديمة داخل IndexedDB من الإصدار السابق تظهر بطاقة «استيراد البيانات القديمة» في شاشة التهيئة — تستوردها مرة واحدة إلى `gym.db` مع تقرير مقارنة الأعداد، وبعدها لا يُستخدم IndexedDB إطلاقًا.

│   │   ├── services/        ← منطق الأعمال (يعمل على الباك-اند فقط)

## نقاط تصميمية مهمة

- **الجلسات**: HttpOnly cookie + توكن مخزّن hashed في جدول `auth_sessions` مع انتهاء متزلّج (12 ساعة). لا يوجد أي توكن أو بيانات حساسة في المتصفح.
- **الصلاحيات**: مفروضة داخل خدمات الباك-اند (`requirePermission`) — إخفاء الأزرار في الواجهة مجاملة UI فقط.
- **تحديثات الواجهة**: `index.html` بلا كاش وملفات `/assets/*` بصيغة hash immutable — التحديث الجديد يظهر فورًا دون «مسح كاش».
- **الترحيلات**: `schema_migrations` يضمن تطبيق ما لم يُطبَّق فقط؛ لا يُعاد إنشاء أو حذف أي بيانات أبدًا.
- **العمل بدون إنترنت**: كل العمليات محلية 100%؛ الاتصال الخارجي الوحيد المحتمل مستقبلًا هو WhatsApp/الترخيص ولا يمس قاعدة البيانات.
- **RTL أصيل**: `dir="rtl"` + Logical Properties، أرقام وتواريخ `ar-EG` وعملة جنيه عبر `src/services/format`.

## حدود معروفة (حالية)

- **عربي فقط** بواجهة واحدة (تصميم مقصود).
- **جهاز واحد**: لا يوجد دعم LAN/أجهزة متعددة بعد (`GYMSYSTEM_HOST` موجود لكنه خارج نطاق هذه المرحلة عمدًا).
- **واتساب يدوي**: قوالب + فتح رابط يدوي؛ لا يوجد مزوّد إرسال تلقائي.
- **مرفقات المصروفات** BLOB داخل SQLite (خارطة الطريق نقلها إلى `Files\`).
- **لا يوجد EXE/installer** بعد — التشغيل عبر `start-gymsystem.bat`.
- تنظيف ملفات صور الأعضاء من القرص عند «الحذف النهائي» تم؛ بقي توثيق قرار النطاق للأقسام (رجال/سيدات) على مستوى الخدمات الأخرى حسب ADR-004.

## ما تبقى (خارطة الطريق)

1. **تغليف EXE/installer** (Tauri/Electron) ليكون الإطلاق ملفًا واحدًا بدون Node ظاهر.
2. نقل المرفقات/الصور إلى `Files\` على القرص بالكامل.
3. دعم أكثر من جهاز داخل الشبكة المحلية عبر توجيه الـ API عمدًا (`GYMSYSTEM_HOST`) مع HTTPS.
