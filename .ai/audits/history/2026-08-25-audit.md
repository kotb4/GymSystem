## Executive Summary

Yassen Mohamed Kotb | 01288536381 is architecturally sound and unusually disciplined for its size: strict TypeScript across client/server, a whitelisted RPC boundary, parameterized SQL everywhere, argon2id passwords, hashed session tokens, append-only financial ledger with uniqueness guarantees, versioned migrations, and a genuinely useful 168-test suite. Static analysis found **no SQL injection, no path traversal, and no secrets in code**.

However, the audit surfaced one **critical authorization gap**: the HTTP restore endpoint (`POST /api/system/restore`) accepts a full database file from **any authenticated user** — no `requirePermission` call exists on that route or inside `importDatabaseBytes`. An ordinary trainer session can replace the live database with an attacker-crafted file and become owner. The sibling endpoints `/api/backups/create` and `/api/backups/download` are similarly ungated, meaning any staff account can download a complete copy of the database (members' PII, finances, password hashes). These routes enforce permissions nowhere; only the RPC-side listing/diagnostics functions do.

Secondary themes: department scoping (`general/men/women`) is enforced only inside `members.service.ts` (7 call sites) while member-scoped operations in subscriptions/payments/attendance/store/classes/CRM accept arbitrary member IDs unchecked (cross-section IDOR between staff); member purge cascades 17 tables correctly but leaves orphaned rows/files behind in the new `files` registry; documentation drift (README describes half the app as unbuilt); and the repository has **zero git commits**, so there is no rollback point for any of this.

All findings below include concrete locations and minimal fixes. Nothing was modified during this audit.

## Findings

### F-01 · CRITICAL · Unauthenticated-to-any-user database replace via `/api/system/restore`
- **Location:** `server/index.ts:316-326` → `server/backups.ts:127-177`
- **Evidence:** Route handler resolves any valid session then calls `importDatabaseBytes(actor, …)` directly. `importDatabaseBytes` validates file format (SQLite header, integrity, users>0) but performs **no** `requirePermission`. Grep confirms `requirePermission` appears in `server/index.ts` only at lines 351/353 (file serving) and nowhere in `backups.ts` import path.
- **Impact:** Any non-owner staff session (trainer/reception) can POST a crafted SQLite DB whose `users` table contains an attacker-known owner login; the server adopts it atomically → full privilege escalation + wholesale data replacement (protective snapshot mitigates loss but not takeover).
- **Fix:** First statement of the restore branch: `requirePermission(actor, "backup.restore");` (permission code already exists). Keep legacy-import's unauthenticated window strictly limited to `owners === 0`.

### F-02 · HIGH · Backup download/create lack authorization
- **Location:** `server/index.ts:287-314` (`POST /api/backups/create`, `GET /api/backups/download`)
- **Evidence:** Handlers call `createServerBackup`/`readSnapshotBytes` with no permission gate; `backup.service.ts` gates only `listBackupEntries` (settings.view) and `pruneBackupsForActor` (settings.view) — creation/recording/recording paths unchecked.
- **Impact:** Any authenticated role can download complete `.gymbak` snapshots (all PII, salaries, argon2 hashes) or fill disk with snapshots. Severity rises further if `GYMSYSTEM_HOST` is ever bound to LAN.
- **Fix:** Enforce `backup.create` on create and `backup.restore` (or a dedicated `backup.download`) on download inside the HTTP handlers, mirroring the RPC-side pattern.

### F-03 · HIGH · Version control: zero commits
- **Location:** repository root (`git rev-list --count HEAD` → fatal: unknown revision)
- **Evidence:** Entire tree untracked on `master`; no commit has ever been made.
- **Impact:** No rollback point; any bad automation/AI edit or disk failure is unrecoverable; audits cannot diff over time.
- **Fix:** Make an initial commit now (exclude `node_modules/`, `dist*/` via existing `.gitignore`), then commit per logical change. Operational, not code.

### F-04 · MEDIUM · Department scoping enforced only in members service
- **Location:** `assertDepartmentAccess` call sites: `members.service.ts:177,256,327,386,547,572,597` — and nowhere else (project-wide count: 7)
- **Evidence:** Member-scoped operations elsewhere accept raw `memberId` without department checks: `subscriptions.*` (create/list/freezes/freeze/renew), `payments.recordPayment/listPayments`, `attendance` check-in/analytics, `store` credit sale/debts, `classes` bookings, `body_assessments`, `crm` messages, `training_plans`.
- **Impact:** Men-section staff can read/write women-section members' financial and health records by ID (UI hides rows; backend does not). Contradicts documented business rule "services enforce assertDepartmentAccess".
- **Fix:** Either resolve-and-check the member's department inside each member-scoped service entry (reuse a shared helper), or document scoping as members-module-only after human decision.

### F-05 · MEDIUM · Member purge orphans `files` rows and disk bytes
- **Location:** `src/core/services/members.service.ts:606-630` (purge cascade) vs `server/files.service.ts` (registry)
- **Evidence:** Cascade deletes 17 child tables but never touches `files` referenced by `members.photo_file_id`, nor member-scoped `inbody_report` uploads; disk objects under `Files\<kind>\` survive.
- **Impact:** Permanent disk growth and dangling metadata for purged members (privacy residue for hard-deleted identities).
- **Fix:** Inside the same transaction: collect `photo_file_id` + inbody report file IDs for the member, `DELETE FROM files` and unlink disk paths after COMMIT (or best-effort post-commit cleanup), keeping FK-safe ordering.

### F-06 · MEDIUM · Documentation drift: README contradicts implementation
- **Location:** `README.md:146-154` ("known limitations": Store/POS, Classes, Employees, InBody, CRM listed as schema-only) and `README.md:140` (claims 107 tests)
- **Evidence:** Implemented services/pages/tests exist for all five modules; current suite is 168 tests / 13 files (executed this audit).
- **Impact:** Humans and AI agents basing decisions on README will re-plan existing features or skip regressions.
- **Fix:** Run `/docs` to resync README/.ai with verified state (docs-only change).

### F-07 · LOW · `GET /api/files-meta/:id` skips per-kind permission
- **Location:** `server/index.ts:367-376`
- **Evidence:** Byte-serving route checks `members.view` + `permissionForKind(...)`; metadata route checks nothing beyond session.
- **Impact:** Metadata (original filename, mime, size, timestamp) readable by any role given a file UUID; UUIDs are random → low practical exposure.
- **Fix:** Apply the same two-step permission pattern as the bytes route.

### F-08 · LOW · Permission-config RPC readable by all roles
- **Location:** `server/rpc.ts` (permissions group, `p()` entries) vs page gating `users.view` (`nav-routes.ts`, `routes/index.tsx`)
- **Evidence:** `permissions.getRolePermissions`/`getAllPermissions` are plain functions callable by any authenticated session.
- **Impact:** Minor config disclosure; no mutation risk (`setRolePermissions` correctly requires `settings.edit` and refuses owner).
- **Fix:** Acceptable as-is for UI needs; alternatively switch to `a()` + `requirePermission("users.view")`.

### F-09 · LOW · RPC consistency checker false-negatives
- **Location:** `scripts/check-rpc-consistency.cjs` vs `server/rpc.ts:64-97`
- **Evidence:** Inline `{fn, actor:true}` registry entries (`members.setMemberPhoto/removeMemberPhoto`) reported as "client calls missing from registry" though fully functional.
- **Impact:** Tool noise trains users to ignore checker output.
- **Fix:** Teach the checker the inline-entry shape, or migrate those two entries to `a()` wrappers.

### F-10 · LOW · Direct fetch bypassing API layer
- **Location:** `src/contexts/auth-context.tsx:61,134`
- **Evidence:** `fetch("/api/auth/me")` called directly instead of through `src/api` wrapper (convention: AGENTS.md §6).
- **Impact:** Consistency only; no security effect.
- **Fix:** Route through `src/api/client.ts` (`MeResponse`) helpers.

### F-11 · LOW · Session cookie omits `Secure` attribute
- **Location:** `server/index.ts:128-138`
- **Evidence:** `HttpOnly; SameSite=Strict; Path=/; Max-Age=…` — no `Secure`.
- **Impact:** None on plain-HTTP localhost; cookie would travel over HTTP if ever LAN-bound.
- **Fix:** Add `Secure` when introducing HTTPS/LAN support; document in ADR at that time.

### F-12 · LOW · Leftover temp artifact
- **Location:** `scripts/tmp-store-page.txt`
- **Evidence:** Stray scratch file committed to working tree.
- **Impact:** Hygiene/noise.
- **Fix:** Delete (requires human approval since outside audit write scope).

### F-13 · LOW · Per-account-only brute-force throttling + large body cap
- **Location:** `auth.service.ts:23-24` (lockout 5×300s per account), `server/index.ts:29` (`MAX_BODY_BYTES = 256 MB`)
- **Evidence:** No IP/session-level throttling; 256 MB JSON/octets accepted on all POSTs.
- **Impact:** Irrelevant on loopback single-operator machine; becomes relevant the day LAN binding is enabled.
- **Fix:** Pair with the future `GYMSYSTEM_HOST` ADR: reverse-proxy limits or per-route caps.

## Verified-good (audited, no findings)

- **SQL injection:** every dynamic fragment comes from hardcoded condition strings / `?` placeholders / hardcoded table arrays (`backup.service.ts:116,212`, `backups.ts:104` included). No user input reaches SQL text.
- **Path traversal:** snapshot filenames validated against `^[A-Za-z0-9._-]+$` + explicit `..` block (`backups.ts:16-24`); static serving normalizes and prefixes DIST_DIR (`index.ts:389-397`); uploaded files stored under `crypto.randomUUID()` names with stripped extensions (`files.service.ts:73-77`).
- **Uploads:** kind whitelist + MIME whitelist + 2 MB cap + non-empty + name required (`files.service.ts:60-92`).
- **Sessions:** 256-bit random tokens, SHA-256 at rest, 12 h sliding TTL, expiry pruning, logout destruction, `HttpOnly; SameSite=Strict` cookies (`sessions.ts`, `index.ts:128-138`).
- **Passwords/setup:** argon2id; setup refuses once an owner exists; lockout 5 fails → 300 s (`auth.service.ts`).
- **Ledger integrity:** `UNIQUE(ref_table, ref_id, entry_type)`; double-reversal guards in void/cancel paths with regression tests (`finance.test.ts` — both orderings pass).
- **Purge cascade:** FK-safe 17-table order inside one transaction, with cascade-count audit (`members.service.ts:606-630`; dedicated test passes).
- **Transactions:** multi-write invariants (payment+ledger+audit, cancel reversals, store sale+debt+stock, salary pay, booking session-consume, migration application, DB adopt) consistently wrapped.
- **RPC boundary:** unknown service/fn → FORBIDDEN; `a()` injects `(db, actor)`; frontend has no DB access path.
- **Conventions:** no `console.log` in services/db/core; i18n coverage test enforces translation completeness (green).
- **Build/tests:** typecheck client+server clean; 168/168 tests pass; migrations append-only v1–v6 tracked in `schema_migrations`.
